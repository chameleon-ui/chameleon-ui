## 3. 怎么做

### 3.1 主题市场

1. 新建应用或服务（路径写入工程目录说明书）：浏览、详情、安装、上架申请。  
2. 安装调 `install-core` + 用户指向的 registry。  
3. 上架流水线自动跑：rules 校验、RTL 快照抽样、license、a11y 自动检测。  
4. **拒绝**致敬主题 id 进入付费区；内部名单或命名前缀策略（开会定，例如禁止与官方 8 套同 id）。

### 3.2 纪律包分发

1. 制品 = `design-rules.json` + 可选 Token overlay + `meta.json`。  
2. Registry `type`：`registry:rules` 或等价扩展字段。  
3. 付费：授权服务外置；下载鉴权后仍走同一安装内核。

### 3.3 MCP Apps

1. 评估当时协议成熟度。  
2. 决策树：适配 POC（有 demo） / 仅观察报告（无码）。  
3. 若适配：独立 adapter 包，不进 L1。

### 3.4 文档 21 语

1. 以 contract + ICU 生成文档骨架。  
2. 缺口表：语言 × 页面 × ETA × owner。  
3. 完整版定义：核心组件页 21 语全绿（开会可裁「营销页」）。

### 3.5 合规与移交

1. VPAT 发布到文档站。  
2. 全量性能/a11y 审计报告入库。  
3. 看板：接入回流/Bench 指标结构（可空数据）。  
4. 《建设期移交说明书》：系统权限、域名、密钥轮转、日历、遗留清单。

## 5.5 功能点：预留 · 埋点 · 标记（本阶段矩阵）

> 字典见 [工程约定 §10](../../engineering/工程约定与命名规范.md)。  
> **Phase 4 总原则：上架与交易全链路可审计标记；埋点服务运营看板；致敬主题永不进付费。**

| 功能点 | 预留 | 埋点 | 标记 | 说明 |
| :--- | :--- | :--- | :--- | :--- |
| 主题市场浏览/安装 | 推荐算法预留 | **必做** 安装经内核 `install`；来源可=`market` | listing id；`community-` 前缀策略 | |
| 上架检测 | 人工复审队列预留 | **应做** 检测失败原因聚合事件（无源码） | 检测项 id：`check.rtl` 等 | |
| 致敬主题隔离 | — | — | **必做** 官方/致敬 id 黑名单标记，阻断付费上架 | 红线 |
| 纪律包分发 | 优惠券等商业预留 | **应做** 下载/安装事件；付费结果仅状态码 | `type=registry:rules` | 支付不进核心库 |
| MCP Apps | 若「仅观察」：报告预留下期 | 若适配：安装埋点同前 | adapter 包名 | |
| 21 语文档 | 营销页缺口 ETA | — | 路由 locale；缺口表 `LEGACY-*` | |
| VPAT 正式发布 | 下一修订预留 | — | 文件名含 version；状态=`published` | |
| 北极星看板 | 未达标指标空态预留 | **必做** 消费既有 telemetry/bench，不新造平行事件名 | `bench.*` / `telemetry.*` | 达标非 M4 硬门禁 |
| 建设移交 | — | — | 遗留 `LEGACY-YYYY-NNN`；权限清单 | |
| 新打点 SDK | **禁止**另起炉灶 | **禁止** | — | 一律扩展事件字典 |

## 5.6 性能指标（本阶段）

| 指标 | 本阶段要求 | 通过标准 |
