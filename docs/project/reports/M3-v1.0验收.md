## 4. A3.4 证据（私有 Registry）

协议：`chameleon-registry/v1`。企业相对公网的差异是 **鉴权 + 网络位置 + 命名空间**，不是第二套 item schema，也不是旁路 install-core。

| 检查 | 结果 |
| :--- | :--- |
| 无 Token 访问 `/v1/...` | HTTP 401 |
| 错误 Token | HTTP 401；审计日志不含 Token |
| `/health` | 无鉴权；`telemetry: off` |
| `GET .../public/items/button` | 与 bundled 同构：`id/type/name/files` + `namespace=public` + `version=0.0.0` |
| `acme` namespace | `button` 版本 `0.9.0` / `1.0.0` / `1.1.0`；未钉版本取 latest `1.1.0` |
| 安装 | `prepareInstall` → `createInstallKernel` → 写临时目录；断言文件内容 |
| 遥测 | 默认不传 hook；`CU_TELEMETRY` 未开则无事件。钩子存在时事件名仍为 `install`，`source=cli\|mcp` |
| 无 URL | `createRegistryClientFromEnv` → `kind=bundled`，不发网络 |

复现：

```
cd chameleon-ui
corepack pnpm@9.15.0 --filter @chameleon-ui/registry-private test
corepack pnpm@9.15.0 phase3:gates
```

环境变量（卡片）：`CU_REGISTRY_URL`、`CU_REGISTRY_TOKEN`。可选 `CU_REGISTRY_NAMESPACE`（默认 `public`）。

**预留（未实现，禁止当成已具备）**：IdP SSO、mTLS 客户端证书、按租户发 Token、K8s Operator。HTTPS 仅在同时提供 `CU_REGISTRY_TLS_CERT` + `CU_REGISTRY_TLS_KEY` 时启用（服务端证书，不是 mTLS）。

## 6. 遥测告知（telemetry-notice.v1）

- 默认关。`CU_TELEMETRY=1` 才挂钩。
- 私有 Registry 服务本身不发 `install` 事件；安装回流仍只在 install-core。
- theme-studio 导出成功只发本机 `cu:theme-studio:export` CustomEvent，不上报。
- 无网络分析 SDK。
- 退出：`chameleon telemetry-off`（有 hook 时发 `opt_out`）。
