## 1. 目的

检验官方 8 套致敬主题在标准 AppShell + 常用控件上是否能被「一眼认出」。通过线是 **正确率 ≥80%**。未完成真人会话之前，禁止在 README、站点、看板或口头宣传中使用该数字。

## 2. 谁来测

| 项 | 规定 |
| :--- | :--- |
| Owner | **待指定**（签字前不得关 T9.5） |
| 测试者 | 建议 **≥5 名**独立被试；优先未参与这 8 套 token / overlay 绘制的人 |
| 排除 / 声明 | 若被试刚用过 Demo 主题切换器（`?theme=`），须在 `testerId` 或备注里声明 prior exposure |
| 语言 | 建议全员使用同一 Locale。默认 `/?view=blind&locale=en`；中文主试可用 `locale=zh-CN` |

## 3. 样本量建议

| 层 | 建议 | 说明 |
| :--- | :--- | :--- |
| 单会话 | 8 主题 × 2 = **16** 题，会话内洗牌 | Harness 固定此结构 |
| 聚合 | ≥5 名独立被试 → ≥80 次观察 | 不足时**不宣称**、不勾选看板 |
| 通过 | 聚合 `correct / answered ≥ 0.8` | `unknown` **计错**；未答不算进分母 |

单次 16 题会话的分数只属于该被试，**不能**单独用来勾选「≥80%」。

## 4. 界面池与 Harness

- 应用：`apps/internal-demo`
- URL：`http://127.0.0.1:5175/?view=blind`
- 启动：在 `chameleon-ui/` 下 `$env:PATH` 含 corepack shims 后执行 `corepack pnpm@9.15.0 demo`，另开 `corepack pnpm@9.15.0 demo:blind`（或 `demo:blind -- --with-demo`）
- Schema：[`schemas/blind-test-result.schema.json`](./schemas/blind-test-result.schema.json)
- 入库：`pnpm blind:validate` → `pnpm blind:ingest` →（≥5 人后）`pnpm blind:ingest -- --promote`
- 刺激：与官方 VR 相同的 **AppShell + common-10**（Button / Icon / Typography / Input / Select / Checkbox / Dialog / Tabs / Stack / Spinner）
- 主题全集（闭集选项）：`line` · `silver-arrow` · `stuttgart` · `corsa` · `cupertino` · `siren` · `wechat` · `ant-blue`，外加 `unknown`
- Chrome **不展示**当前 theme 名；地址栏 **不带** `theme=`
- 记录只在本机：复制 / 下载 JSON，无分析后端

## 5. 施测步骤

1. 打开盲测 URL。读须知。填写 tester id。勾选诚实声明后点「开始会话」。
2. 看当前界面（不要打开开发者工具，不要查看 `data-theme`）。
3. 从 8 个官方 id 或 `unknown` 中选一个，点「锁定选择」。当场不揭晓对错。
4. 重复至 16 题结束。
5. 用 **复制 JSON** 或 **下载 JSON** 导出。文件名默认 `盲测结果.<testerId>.json`。
6. 把导出物交给 owner，按 §6 / operator kit 入库。多人则每人一份，由 owner 用 `blind:ingest -- --promote` 汇总，**禁止**把某一份的 session `rate` 直接写成产品宣称。

## 6. 如何填写结果文件

占位（未跑）：[`盲测结果.pending.json`](./盲测结果.pending.json)，必含 `"status": "not_run"`、`"rate": null`。

真人完成后：

1. 将 harness 导出的 JSON 保存为 `docs/project/reports/盲测结果.json`（可另存 `盲测结果.<testerId>.json` 再汇总）。
2. 汇总文件仍用同一 schema：`chameleon-ui/blind-test-result/v1`。
3. `status` 改为 `"complete"` **仅当**已按 §3 收齐约定样本量（或 owner 书面接受较小样本且 **不宣称 ≥80%**）。
4. `rate` **只能**是 `correct / answered` 的计算结果（0–1 小数），来自 `trials[]`。
5. 每条 trial 必须有：`themeId`、`guess`、`correct`、`timestamp`。
6. `owner` 保持或改为实名；未指定则仍为 `待指定`。

字段要点：

```json
{
  "schema": "chameleon-ui/blind-test-result/v1",
  "status": "complete",
  "rate": null,
  "owner": "待指定",
  "trials": [
    {
      "index": 0,
      "themeId": "line",
      "guess": "line",
      "correct": true,
      "timestamp": "2026-08-14T01:00:00.000Z"
    }
  ]
}
```

上面示例里的 `"rate": null` 表示：**本文不得填写任何编造数字**。真实 `rate` 只允许从已发生的 `trials` 算出后写入导出物，禁止在协议或看板里提前写上 80%。

## 7. 通过规则

- 口径：`rate = correct / answered`；`unknown` 为错误。
- 通过：聚合后 `rate ≥ 0.8`。
- 未达：保持不宣称；看板仍为 `[ ]`。
- 书面放弃：另出放弃函，README 继续禁止「一眼认出 ≥80%」。

## 8. 禁止（硬）

- **禁止手打一个认出率百分比**（包括 80%、≥80%、约八成、四舍五入凑线）。
- 禁止在 `盲测结果.pending.json` 把 `rate` 改成非 `null`。
- 禁止用开发者工具、源码、`data-theme`、主题 CSS 文件名、或中途对答案来答题。
- 禁止把单会话 harness 屏幕上的答对题数写成已发布指标。
- 禁止在真人聚合完成前勾选 PHASE2 / PHASE3 / PHASE9 的 ≥80% 项。
