# كيف يعمل نظام الأطراف الثلاثة

> **العربية · [简体中文](three-end-system.md) · [English](three-end-system.en.md) · [繁體中文（香港）](three-end-system.zh-HK.md)**

«تثليث الأطراف» يعني أن Chameleon UI يستخدم **مجموعة المكونات نفسها** للتكيّف تلقائيًا مع **ثلاثة أشكال للأجهزة** — الهاتف (390) والتابلت (768) وسطح المكتب (1280) — بدلًا من كتابة كل شكل على حدة. توضح هذه الوثيقة **الآلية الحقيقية**.

> المرافِق: تغطية ترجمة الرموز في [`token-system.ar.md`](./token-system.ar.md)؛ وبناء موضوع في [`creating-a-theme.ar.md`](./creating-a-theme.ar.md).

---

## 0. أوضح أولًا مفهومًا: React / Vue مقابل «الأطراف الثلاثة»

قبل مناقشة الأطراف الثلاثة يجب توضيح بُعد «الإطار» لتجنّب الخلط بين «طرفين» مختلفين:

- **بُعد الإطار = React، Vue** (طبقتا محوّل التقديم). انظر القسم التالي.
- **بُعد نافذة العرض/الشكل = الهاتف، التابلت، سطح المكتب (تثليث الأطراف)**. هذا هو معنى «الثلاثة أطراف».

البعدان متعامدان: React و Vue **يكلاهما ينفّذ تثليث الأطراف**. لذا «تثليث الأطراف» ليس حصريًا لأي إطار — إنها قدرة مشتركة لنظام التصميم.

### لماذا نفصل React و Vue؟

لأن **النواة عديمة الشكل (Ark UI / Zag) مُعبَّأة حسب الإطار** ولا يمكنها مشاركة الواجهات عبر الأطر:

| | خط React | خط Vue |
| :--- | :--- | :--- |
| النواة عديمة الشكل | `@ark-ui/react` → `primitives` | `@ark-ui/vue` → `primitives-vue` |
| أغلفة المكونات | `components` (`*.tsx`) | `components-vue` (`*.vue`) |
| الحزم الموحّدة | `@chameleon-ui/react` | `@chameleon-ui/vue` |

لكن الخطين **يشاركان نفس طبقة التصميم**، لذا ليسا «مكتبتين عشوائيتين» بل «**نظام تصميم واحد × محوّلي تقديم**»:

- **فهرس واحد**: `components/catalog.json` (109 مكونات) هو المصدر الوحيد؛ و Vue **لا يملك فهرسًا خاصًا**.
- **عقود متطابقة**: يتشارك React و Vue `contract.json` (سلوك `Button` من حيث props/a11y/RTL متطابق).
- **رموز / i18n / مواضيع واحدة**: `tokens` و`i18n` (21 لغة) و`themes` مشتركة بين الطرفين.

الخلاصة: **تعيش قرارات التصميم في طبقة L1 المشتركة (رموز/عقود/i18n)؛ ويقتصر دور React/Vue على «ترجمة» نفس الدلالات إلى مكونات كل إطار.** هذا هو أساس «اتساق عبر الأطر»، وسبب فصل React/Vue بدل بناء واحد فقط.

## 1. ثلاثة أطراف = ثلاث مستويات نقاط قطع

الأساس المادي هو ثلاث **رموز نقاط قطع** (معرّفة في `packages/tokens/src/core/breakpoint.json`):

| المستوى | الرمز | القيمة | المدى |
| :--- | :--- | :--- | :--- |
| الجوال | `breakpoint.mobile` | `0px` | `< 768px` |
| التابلت | `breakpoint.tablet` | `48rem` | `768 – 1279px` |
| سطح المكتب | `breakpoint.desktop` | `80rem` | `≥ 1280px` |

تُعرب نقاط القطع بـ **rem** (وليست px) لتتبع حجم الخط الجذر وتُكبَّر دون تشوّه. هذا هو مصدر الأرقام `390 / 768 / 1280` (عند جذر 16px).

---

## 2. الآلية الجوهرية: استعلامات الحاويات (`@container`) بدل `@media`

تستخدم المناهج التقليدية `@media (min-width: 1280px)` مربوطة بـ**نافذة العرض**. يستخدم Chameleon UI **استعلامات الحاويات**: ينظر المكوّن إلى عرض **حاويته الخاصة**، وليس نافذة المتصفح بأكملها.

```
العرض الخاص للمكوّن =  < 20rem    → شكل الهاتف
                         48–80rem  → شكل التابلت (شريط قابل للطي)
                        ≥ 80rem    → شكل سطح المكتب (شريط جانبي دائم)
```

**لماذا استعلامات الحاويات؟**
- يجب أن يتحول المكوّن بناءً على **عرضه المتاح** — مدمجًا في شريط جانبي ضيق مقابل ملء نافذة عريضة — لا بحسب نافذة المتصفح.
- على سبيل المثال يستخدم `Navigation` (انظر §4) `@container navigation (min-width: …)` لتحديد شكله (جانبي / قابل للطي / تبويب).

**ضمان البوابة**: **يُمنع** أن تستهلك CSS للمكونات نقاط قطع `@media` مباشرة (يحجزها stylelint `chameleon/no-breakpoint-literal`)؛ فالاستجابة للعرض تتم دائمًا عبر `@container` — فلا يمكن تجاوز الآلية وتبقى متسقة.

## 3. الكثافة والمكونات تتغير حسب الطرف

تختلف الأطراف الثلاثة ليس في **التخطيط** فحسب، بل في **الكثافة**: نفس المكوّن أكثر اتساعًا على الهاتف (ملائم للمس) وأكثر انضغاطًا على سطح المكتب.

### 3.1 رموز الكثافة (`density.json`)

| الرمز | العامل |
| :--- | :--- |
| `density.compact` | `0.875` |
| `density.standard` | `1` |
| `density.comfortable` | `1.125` |

الحد الأدنى لأطوال المكونات: `control.size.{compact,standard,comfortable}` = `2.25 / 2.5 / 2.75rem` (أي 36 / 40 / 44px عند جذر 16px). و`touch-target.min` = `2.75rem` (44px، حد إمكانية الوصول باللمس).

### 3.2 الكثافة الافتراضية حسب الطرف

يوفر `@chameleon-ui/tokens/density.css` (المولّد بـ `scripts/density-css.mjs`) **كثافة افتراضية تعتمد على نقاط القطع**:

| الطرف | الكثافة الافتراضية |
| :--- | :--- |
| الجوال | `comfortable` (مريحة، هدف لمس 44px) |
| التابلت | `standard` |
| سطح المكتب | `compact` |

**قناتان للتغيير**:
- **مستوى نافذة العرض**: تغطي `@media` غلاف الصفحة (تتغير كثافة الصفحة كاملة مع عرض النافذة).
- **مستوى الحاوية**: تغطي `@container app-shell` «غلافًا ضيقًا داخل نافذة عرض عريضة» (مثل لوحة صغيرة داخل dashboard) — سيناريو `A5.3`.
- **تجاوز صريح**: `<html data-density="compact|standard|comfortable">` يفرض مستوى بغضّ النظر عن نقاط القطع.

**مهم**: التطبيق الذي يستهلك `@chameleon-ui/tokens/css` **يجب أيضًا `import '@chameleon-ui/tokens/density.css'`**، وإلا لن تتغير `--cu-density-active` / `--cu-control-size-active` حسب نقاط القطع.

## 4. تنقل الأطراف الثلاثة: واجهة واحدة، ثلاثة أشكال

غلاف التطبيق (`AppShell`) والتنقل (`Navigation`) هما أوضح تجسيد — **نفس بيانات `items` تعرض ثلاثة أشكال عند ثلاثة عروض**:

| الطرف | شكل Navigation |
| :--- | :--- |
| الهاتف (حاوية ضيقة) | **Tab شريط سفلي** (مضغوط)، وفائض داخل `More` |
| التابلت | **شريط قابل للطي** |
| سطح المكتب (حاوية عريضة) | **شريط جانبي دائم** |

التنفيذ: يستخدم CSS لـ `Navigation` استعلامات الحاويات للتبديل حسب `min-width: 48rem / 80rem`:

```css
@container navigation (min-width: 80rem) { /* شكل الشريط الجانبي */ }
@container navigation (min-width: 48rem)  { /* شكل الشريط */ }
@container navigation (max-width: 20rem)  { /* شكل التبويب */ }
```

مكونات الأطراف الثلاثة المرافقة: `AppShell` (هيكل التطبيق الثلاثي) · `SafeArea` (حواف النوتش / شريط الإيماءات) · `ActionSheet` (لوحة الإجراءات السفلية للهاتف) · `Navbar` / `NavigationTitle` (تنقل أفقي/متراكم).

---

## 5. سير العمل: لماذا «كود واحد، ثلاثة أشكال» لا يفشل

- **الأنماط**: يكتب نمط المكوّن الواحد المستويات الثلاثة باستعلامات الحاويات؛ وتحمل خصائص CSS المخصصة (`--cu-*`) قيم الرموز.
- **JS/المنطق**: نفس واجهة المكوّن (`items`، `locale`، props) — تبديل الشكل هو CSS خالص ولا يغيّر بنية البيانات.
- **العقود**: يسجل `contract.json` `responsive` وسلوك الأطراف الثلاثة، ويتشاركه React و Vue.

إذن «تثليث الأطراف» ليس ثلاثة تنفيذات بل **عقد واحد + منطق تفاعلي واحد + أنماط استعلام حاويات**، تتحول تلقائيًا عند ثلاثة عروض.

---

## 6. فحص ذاتي سريع

1. تبديل الأطراف الثلاثة لا يعمل؟
   - تأكد من استيراد `@chameleon-ui/tokens/density.css` (انظر 3.2).
   - تأكد أن stylelint لم يرفض نقطة قطع `@media` (يجب `@container`).
2. مكوّن مدمج في حاوية ضيقة لا يصغر؟
   - تحتاج الحاوية إلى `container-type: inline-size` (مثل حاوية Navigation، AppShell).
3. `data-density` لا يعمل؟
   - لا يوجد `density.css`، أو إملاء `[data-density]` لا يطابق `compact|standard|comfortable`.
