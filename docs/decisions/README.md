# 架构决策记录（ADR）

这里记录 Chameleon UI 的重大架构决策和当时的理由。想改动某个结构性选择时，先读对应的 ADR，确认当时的约束是否已经变化。

每条 ADR 包含：状态、背景、决策、已否决的备选、后果、重估条件。状态取值：已接受、已提议、已废弃。

## 何时新增 ADR

满足任一条件即可：

- 影响多个包的结构变化；
- 引入或替换地基级依赖；
- 改变消费者可见的契约（包名、exports、peer 矩阵）；
- 否决了一个看似合理的方案（否决本身也值得记录）。
